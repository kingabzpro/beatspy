METHOD

How this benchmark works

Six steps run identically for every model. Fixing them is the point: a difference on the board is then a difference between models, not between setups, and any run can be replayed from its own artifacts.

Frozen data · typed questions · fixed policy · replayable scores

  1. Freeze the market.Prices are downloaded once into a content-addressed snapshot. Every run over that window re-uses the same bytes, so a score can never change because the data did.
  2. Build the state.One compact JSON per decision date, holding only data dated on or before it, with the token budget enforced before anything is sent. It carries the pool's trailing hit rate against SPY, so a model can see when 0.5 is an optimistic answer for a typical name.
  3. Ask typed questions.One probability question per investable asset, phrased identically for every model: will it beat SPY over the next few sessions? The optional forms ask the same name as a two-way choice and a five-level rank. Answers must be typed probabilities; a refusal is recorded as missing coverage, never invented.
  4. Size the book.A fixed, deterministic policy turns probabilities into target weights: the book spreads across the pool by conviction, a trade fires only when a weight moves past the rebalance band, and the index is never bought. The rule was written down before results were seen and is recorded in every run.
  5. Fill the orders.Only weights that moved past the band become orders, and they fill at the next session's open with fees and slippage applied. No decision can trade on a price it has already seen.
  6. Score it twice.Calibration first (Brier, Brier skill, AUC, reliability bins), then the portfolio the answers built: return, Sharpe and drawdown against SPY and deterministic baselines such as equal weight and 60/40.

What keeps it honest

No look-ahead.The state holds only data dated on or before the decision date. The adversarial audit tampers with every later price and requires the earlier decisions to come out byte-identical.

Missing stays missing.An unanswered question is never scored and carries no conviction, so a provider failure cannot become a trade. Coverage is printed on every run.

Replayable.Each run ships its state hash, decisions, fills and metrics, and beatspy verify re-derives the scores offline, requiring exact agreement.

Uncertainty is reported.Returns and excess carry block-bootstrap intervals clustered by decision date, and every calibration score carries a permutation p-value: one six-month window cannot prove an edge.
