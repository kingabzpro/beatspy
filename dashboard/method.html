METHOD

How this benchmark works

Six steps run identically for every model, so a difference on the board is a difference between models, not between setups.

  1. Freeze the market.Prices are downloaded once into a content-addressed snapshot; every run re-uses those bytes.
  2. Build the state.One compact JSON per decision date, holding only data dated on or before it, with the token budget enforced before it is sent.
  3. Ask typed questions.One probability question per asset, phrased identically for every model. Answers must be typed probabilities; a refusal counts as missing coverage, never invented.
  4. Size the book.A fixed policy turns probabilities into weights across the whole pool. The index is never bought, and the rule was recorded before any result was seen.
  5. Fill the orders.Trades fire only when a weight moves past the 2% rebalance band, and fill at the next session's open with fees and slippage. Most names sit inside the band, so a typical weekly decision is mostly holds: on the published board models keep 52% to 91% of the book steady.
  6. Score it twice, on three windows.Calibration first (Brier, Brier skill, AUC, reliability bins), then the portfolio the answers built, against SPY and fixed baselines. The same steps run on three consecutive six-month windows, so a model must hold up in a rally, a flat stretch, and a run it cannot simply ride; the board shows each window and the average.

How a probability becomes buy, hold, or sell

The models never say buy, hold, or sell.Each answers one typed question per asset - will it beat the benchmark over the coming five sessions - and returns a probability. Half the book is spread evenly; the other half follows conviction, each probability's distance above that week's own mean.

The 2% band decides the trade.A name is bought when its target weight sits more than 2 percentage points above what is held, sold when it sits more than 2 below, and held inside the band, where nothing trades and no fee is paid. A name leaving the pool is always sold, and the first decision is all buys from cash.

Holds measure temperament.The share of holds is not a setting; it falls out of how stable a model's probabilities are. On the current board it runs from about 51% of weekly name-level decisions (D3 Turbo, roughly half the book reshuffled every week) to about 88% (Span-01 free, about three names traded per week), and the calmer models pay less in fees and slippage.

What keeps it honest

No look-ahead.The state holds only past data, and an audit tampers with every later price to prove earlier decisions cannot change.

Missing stays missing.An unanswered question is never scored and carries no conviction, so a provider failure cannot become a trade.

Replayable.Each run ships its state hash, decisions, fills and metrics; beatspy verify re-derives the scores offline.

Uncertainty is reported.Returns carry block-bootstrap intervals and every calibration score a permutation p-value: one window cannot prove an edge.

Protocol v2 (protocol 6), from 2026-10-23

Why it exists.Under protocol 5 the state carried only price momentum. Measured across every decision, model probabilities tracked the last five days of returns at rank correlation +0.75 for the strongest follower: the models were largely reading one momentum column and echoing it, and no answer type (yes/no, two-option choice, five-level score) changed that. v2 hands them more to read.

What changed.Every asset row now also carries RSI-14 (reversal pressure), 30-day realized volatility (risk), distance from the 52-week high (level), a 10-vs-50-day volume ratio (attention), and a sector label (what the name is). The question text drops a filler key and phrases a one-day horizon grammatically. The token budget rose from 1,800 to 2,900 to carry the wider rows; no provider truncated the wider state (each one's own token count confirms it).

What did not change.The pool, the windows, the sizing policy, the fees, and the scoring. v2 runs are scored on the same frozen prices and labels, so a model's v2 row and its protocol-5 row on the same window answer the same market question with different information. The two protocols are not comparable, so the board scores v2 only and every protocol-5 run lives in the archive, still replayable, still linked.
